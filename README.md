## 双子岛主线

v0.4 的首页有两座可进入的3D任务岛，围绕现实互联网电商平台与海外移动支付案例展开，所有企业事实有来源，业务表格与决策后果明确标为教学仿真。

| 主线 | 扮演角色 | 8 个连续阶段 |
|---|---|---|
| TikTok Shop 用户增长岛 | 用户增长产品经理，双十一业务场景 | 指标字典 → 用户分层 → DNC拉新诊断 → MAC促活留存 → 召回与激励 → A/B与ROI → 协同上线 → 效果评估 |
| 蟹黄酱出海岛 | 中国品牌GTM负责人 | 市场选择 → STP → SKU与食品条件 → 定价 → 渠道与支付 → 整合营销 → 首发WBS与履约 → 复购现金扩张 |

**16 阶段、96 道实战题、48 项阶段概念、16 份开放方案。** 每阶段包含可核查案例、仿真数据表、三种业务策略、单选／多选／数值／行动排序，以及下一阶段交接。选择会改变可累计的项目预算、准备与信任量表；不是实际经营收益预测。

DNC/MAC 使用明确训练定义，**不是TikTok Shop内部官方口径**：DNC为指定时区当日首次有效支付去重购买用户；MAC为自然月有效支付去重购买用户。退款、身份与截止点由任务字典约定。用户提供的岗位JD是平台线设计依据。

## 从一场业务任务开始

1. 选择一座岛，接受岗位任务。
2. 阅读现实案例的国家、时间、来源和边界，再读独立仿真表格。
3. 比较业务方案，理解本阶段投入与下一阶段影响。
4. 完成6道不同题型的实战题，查看解释并补练。
5. 写至少40字的阶段方案、自查至少3项，提交后解锁下一阶段。
6. 在双岛任务档案中查看决策、资源和文字交付，导出／导入备份。

新主线**不含跑酷**。开放方案是自查，不是AI评分；全部数据表是固定业务训练材料，预算／准备／信任采用显式教学规则，不声称市场动态预测。完整机制见[双子岛说明](docs/product/twin-campaigns.md)。

## 本地运行

需要 Node.js 20 或更新版本。

```sh
git clone https://github.com/KeicyZhu/xiaoyu-business-island.git
cd xiaoyu-business-island
npm run dev
```

打开 `http://127.0.0.1:4173/`。

Three.js 0.180.0 已固定在 `src/vendor`；运行、测试和构建不需要联网安装依赖或配置密钥。

```sh
npm test
npm run build
```

`dist/` 是可托管的静态产物。本地服务与构建仅提供允许的 HTML、JavaScript、CSS、SVG 和许可文件；不能直接托管包含私人资料的整个开发目录。

## 质量与范围

v0.4 包含自动化状态／课程／跑酷／构建测试，以及真实浏览器中的 11 关通关、存档恢复、手机布局、名称常显、上下文丢失／恢复和存储失败验证。具体检查命令在架构文档中。
